## 各题型的处理

| 题型     | 参考客户端中可核实的处理                                  | 课伴0.8.6的处理                                                          |
| -------- | --------------------------------------------------------- | ------------------------------------------------------------------------ |
| 题型识别 | 读取学习通隐藏题型编号；章节与作业使用不同容器            | 优先读取明确编号，缺失时才根据标题、原生控件推断                         |
| 单选     | 匹配选项字母或文本，读取选中样式，点击对应项              | 按可见字母定位，兼容唯一文本匹配；点击后核对唯一选择                     |
| 多选     | 根据字母集合判断每个控件是否应当选中，识别check_answer_dx | 归一化并去重答案，逐项增减勾选，核对完整集合后提交                       |
| 判断     | 使用独立处理分支匹配选项                                  | 识别文字及已适配的对错图标，按实际语义映射字母；不默认首项为正确         |
| 填空     | 记录空位数量，将返回内容拆分后逐空写入                    | 将blankCount发送给每轮模型，保留空位顺序，数量或中间空项不完整时继续复核 |
| 富文本   | 通过页面世界中的UEditor实例写入，部分页面再点局部保存     | 沿用受限编辑器接口、纯文本构造与提交字段同步，再读取实际值核对           |

章节兼容singleQuesId、before-after、before-after-checkbox；作业兼容questionLi、answerBg等结构。相互嵌套的同一选项容器会去重，避免把一项计为两项。原有TiMu、mark_item、原生radio/checkbox及MOOC适配继续保留。

## 已复现并修复的问题

1. 部分旧版题块、选项容器不在扫描范围内，导致没有识别到题目或选项。
2. 只根据题干关键词推断题型，可能把题干中出现“多选”的判断题识别成多选；连线等题型也可能被误当成单选。
3. 模型返回小写、全角、连写或重复字母时，无法正常回填。现在兼容明确的字母格式；与选项正文存在歧义时要求模型重新给出明确字母。
4. 判断选项只有字母和图标时，没有正确提取图标语义；原先按位置猜对错还可能把反序选项映射反。
5. 填空数量没有发送给模型，也没有进入缓存身份，相同题干的不同空位布局可能误用答案。
6. 过滤空字符串会移除中间空位；答案项数不匹配时也缺少有效的格式反馈，造成有解析却不回填。现在保留位置并触发复核补全。
7. 普通输入框与iframe富文本混用时，收集顺序不等于页面顺序，可能写反空位。现在按页面中的实际顺序处理。
8. 点击过程中整块题目被重新创建时会丢失节点。现在只在题目身份一致且唯一时重新绑定，继续勾选；人工编辑与停止操作仍优先保留。
9. 填空提交记录遗漏空位数量会使提交与解题身份不一致，导致判错反馈难以关联原题。现在两条路径携带相同信息，并验证判错后能够自动重填、再次提交。

题目身份同时用于页面核对和后台缓存，填空数量在两个位置保持一致。未恢复分数阈值、严格模式或低分重试按钮。

## 托管流程对照

本轮按用户选择优先对齐功能和操作流程。以下结论限于已静态核查的客户端分支与课伴离线回归。

| 环节                               | 课伴0.8.7状态                                                                                          |
| ---------------------------------- | ------------------------------------------------------------------------------------------------------ |
| 单选、多选、判断、填空和简答       | 已有独立实现，核对真实值后按设置提交；保留主模型自检和辅助复核                                         |
| 分录、资料题                       | 新增常见文本空位适配，不把编号9/10直接当成不支持题型                                                   |
| 原生/Chosen下拉连线                | 新增逐空选项协议与实际值、显示同步，判错后可自动改答                                                   |
| 本题保存                           | 新增局部保存步骤；确认已保存或相应界面状态后再翻页/整页提交。明确失败才有限重试，未确认时不重复发送    |
| 分页与整页提交                     | 每页独立保存；题干不同但答案相同时也不会漏保存。只有平台明确提交成功才记为完成                         |
| 慢控件和停止                       | 识别忙碌状态后等待，避免反向补点；临时禁用下拉框不减少空位或额外调用模型。停止后撤销尚未执行的字段写入 |
| 播放、文档、任务切换、MOOC课程定位 | 保留原有实现和回归，尚未对全部真实页面证明与参考产品完全等价                                           |
| 公式转图及上传                     | 尚未对齐。参考客户端另有公式转图/上传路径；当前主要使用文本与可编辑正文                                |
| 私有题库和VIP服务端                | 未取得实现；课伴使用用户自配的模型服务，不能以客户端相似推导出相同答案覆盖或准确率                     |

关闭自动填写时不能通过下拉写入路径绕过开关；关闭自动提交时不额外请求服务器保存。人工在模型处理或保存期间改动答案会保留。

## 仍有适配边界

- 拖拽式连线、完形与阅读组合题需要各自的控件适配。参考客户端已核查的自动填答分支也会将未支持的类型标为unsupportedType，不能仅凭题型名称转换函数认定能自动填写所有题型。
- 已知忙碌状态会等待页面响应。没有明确状态的异步控件、超过等待上限的保存请求及不同高校定制页面，仍需要检查实际DOM和事件时序。
- 公式专用输入器、图片作答和第三方跨域编辑器不等同于普通文本框。视觉模型能识题，不表示所有编辑器都能自动写入。
- 任意新页面样式、未知判断图标、特殊字体截图识别及模型自身的知识错误，都不能靠离线夹具保证正确。真实课程验收须与模拟测试分别记录。

## 验证方式

新增answer_adapters_check.py离线套件，覆盖旧章节与作业、原生与自定义选项、反序判断图标、显式题型、答案格式、空位数量与空项修复、缓存隔离、多富文本、混合输入顺序、整题重绘和人工改动。

0.8.7补充连线实际值/Chosen/重复值/判错、分录/资料、慢单多选、本题保存/隐藏正文/失败重试/停止/人工改动/无确认、禁用填写及服务器保存开关、暂停期间排队写入撤销。分页套件验证两页答案相同仍逐页保存，并验证停止后不会执行已排队的嵌套富文本写入。

旧版失败用例先复现，再验证修复。全部模型请求与课程页面均使用独立浏览器配置和模拟接口，不提交真实作业或考试。完整回归还包含原有播放、章节切换、MOOC、模型配置、稳定性、复核及作业考试套件。
